## Выводы и ограничения

- Для анализа оба агента восстановили основные сценарии и отделили дефекты.
  В этом сравнении Codex точнее описал URL и поиск; OpenCode дал более подробную
  навигацию по коду, но её необходимо сверять с фактической маршрутизацией.
- Для модернизации у Codex лучше подтверждены завершение и воспроизводимость:
  записаны реальные HTTP, проверка старой миграции, точности и устаревших котировок.
  OpenCode подготовил полезную основу с провайдерами и тестами, но перед сдачей WIP
  требовал проверки документированных URL, графика и продолжения после лимита.
- Ни один исходный результат нельзя принимать без пользовательской проверки:
  наличие Plotly в HTML и зелёные тесты не гарантировали правильную диаграмму.
  Текущее №4 показывает качество последующей работы Codex в двух реализациях,
  а не самостоятельную победу одного из двух первоначальных агентов.

Исторические версии заново не разворачивались. Результаты исполнения здесь —
сведения журналов и явно отмеченные сообщения пользователя, не новый аудит runtime.
PostgreSQL и его конкурентные блокировки, Redis/worker/beat через брокер,
реальный T-Invest API и production HTTPS не подтверждены. Тесты контрактов и
синхронные задачи этого не заменяют. Мобильная версия не подтверждена:
в соседней ветке попытка проверки размера была прервана, в первой такой проверки
не записано. Различаются версии зависимостей, сценарии и полнота журналов;
обобщать один учебный запуск на все модели, тарифы или проекты нельзя.
